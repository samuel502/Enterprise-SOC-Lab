
# VM Troubleshooting

This document covers technical issues encountered while configuring the virtual machines for the Enterprise SOC Lab, along with troubleshooting steps and observed resolutions.

## 1. Ubuntu VM Freezing Issue

### Problem

Ubuntu VMs running versions 22.04 LTS and 24.04 LTS experienced freezing and kernel watchdog soft lockup errors during installation and operation.

### Suspected Cause

VMware Tools compatibility or other virtualization-related issues were suspected. However, the exact root cause was not conclusively identified.

### Troubleshooting Steps

1. Force-restarted the VM when it became unresponsive.
2. Disabled the `open-vm-tools` service during troubleshooting.
3. Rebooted Ubuntu and observed system behavior.
4. Eventually recreated the Ubuntu VM using Ubuntu Server 22.04 LTS.

### Outcome

The new Ubuntu Server 22.04 LTS VM successfully installed and ran Wazuh, including its manager, indexer, and dashboard.

The exact cause of the earlier freezing remains undetermined.

## 2. DNS Resolution Failure

### Problem

Both Ubuntu and Windows 11 virtual machines experienced DNS resolution failures while using VMware NAT networking.

Attempts to access package repositories returned errors such as:

```text
Temporary failure in name resolution
```

```text
The remote name could not be resolved: 'packages.wazuh.com'
```

These failures prevented software installation and updates.

### Investigation

Several diagnostic tests were performed:

1. Verified that the VMs received valid IP addresses through DHCP.
2. Confirmed that outbound TCP connectivity to `1.1.1.1` on port 443 was successful.
3. Tested DNS resolution using `Resolve-DnsName`.
4. Attempted DNS queries directly against Cloudflare (`1.1.1.1`).
5. Verified that DNS resolution worked on the Windows host.
6. Investigated the host's network adapters and identified an active ExpressVPN TUN adapter.

The VPN adapter was associated with DNS server `100.64.100.1`.

### Resolution

After completely exiting the VPN applications on the Windows host, DNS resolution succeeded inside the Windows 11 VM.

The Wazuh agent installer was subsequently downloaded and installed successfully.

### Likely Cause

VPN-related interference with DNS traffic between the Windows host and VMware virtual machines.

The exact underlying mechanism was not confirmed.

### Recommendation

When performing SOC lab exercises:

- Exit VPN applications on the Windows host if they interfere with connectivity.
- Verify DNS functionality before installing network-dependent software.
- Use consistent VMware NAT networking configurations.
- Re-enable VPN software when needed outside the lab.

## 3. Wazuh Agent Installation Issue

### Problem

The initial Wazuh agent deployment on Windows 11 did not produce a working agent service.

Attempts to start the service failed because Windows could not locate it.

### Resolution

After DNS functionality was restored:

1. Re-ran the PowerShell installation command generated by the Wazuh dashboard.
2. Started the service using:

```powershell
NET START Wazuh
```

3. Verified successful agent registration in the Wazuh dashboard.

### Outcome

The Windows 11 agent was successfully registered and reported an Active status.

- **Agent Name:** WIN11-Client
- **Agent ID:** 001
- **Agent Version:** 4.14.8
- **Status:** Active

## Lessons Learned

- Successful internet connectivity does not necessarily mean DNS resolution is working.
- VPN applications can interfere with virtual machine networking.
- Software installation should be verified through service status and application functionality.
- Troubleshooting should distinguish suspected causes from confirmed findings.
- Maintaining a record of errors and solutions improves reproducibility and future incident investigation.
